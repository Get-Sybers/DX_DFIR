# The host-side Python dependency lock: everything `dxdfir` fronts is
# ansible + the hardened tool containers, and THIS file pins the exact,
# tested resolution of that ansible layer — ansible-core itself, and the
# docker SDK + requests that community.docker's modules (dxdfir_images,
# dxdfir_stack, the lanes) import on the controller. There is no host
# python package any more (the engine logic lives in get-sybers/byakugan,
# the detections in GoDFIR-toolz, both inside images); this lock is the one
# pip surface left.
#
# Consumed with `pip install -r requirements.txt` by
# scripts/setup-environment.sh (online and offline runs alike), the CI
# workflows and .github/tests/molecule-runner.Dockerfile, so every consumer
# resolves identical versions and an unattended upstream release cannot
# shift a dependency under the pipeline. The Ansible COLLECTIONS are pinned
# separately in ansible/collections/get_sybers.dxdfir/requirements.yml.
#
# Regenerate after a deliberate dependency bump, then restore this header —
# and run it on the OLDEST interpreter the pipeline supports (the CI
# version), so the resolution is installable everywhere the lock is
# consumed:
#   python3 -m venv /tmp/lock \
#     && /tmp/lock/bin/pip install ansible-core requests docker PyYAML \
#     && /tmp/lock/bin/pip freeze > requirements.txt
#
